Unit Sprite3DNativeLibs

Description
Functions and Procedures

Description

Where a program's own native libraries are kept on each platform.

Shared libraries a program ships with, such as FFmpeg's, belong in a different place on each platform. NativeLibraryFolders lists, best first, the folders a library is looked for in: the platform's usual place for an application's own libraries, then a dlls/<key> folder beside the executable and in the folders above it, which is where a build run from the source tree finds a repository's dlls folder. NativePlatformKey names the platform as those folders do. 

Platform                Key            Deployed to
Windows 32-bit          win32          beside the .exe
Windows 64-bit          win64          beside the .exe
Windows ARM64EC         win64arm       beside the .exe
macOS Intel             macx64         Sprite3d.app/Contents/Frameworks
macOS Apple silicon     macarm         Sprite3d.app/Contents/Frameworks
Linux 64-bit            linux64        lib beside the executable
Android 32-bit          android32      the APK's lib/armeabi-v7a
Android 64-bit          android64      the APK's lib/arm64-v8a
iOS device             iosarm64       Sprite3d.app/Frameworks
iOS simulator          iossimarm64    Sprite3d.app/Frameworks

An ARM64EC program can load x64 and ARM64EC libraries but not plain ARM64 ones, so win64arm usually holds the same x64 libraries as win64; when run from the source tree, dlls/win64 is looked in after dlls/win64arm for that reason.

Nothing here loads anything. For any thread.

function NativePlatformKey: String;

The platform's name, as used for dlls folders and openh264.json.

Returns

One of the keys in the unit description, such as 'win64'.

function DeployedLibraryFolder: String;

The platform's usual folder for an application's own libraries.

Returns

The folder, with no trailing delimiter, whether or not it exists.

function NativeLibraryFolders: TArray<String>;

The folders to look for the program's own libraries in, best first.

DeployedLibraryFolder; the executable's own folder; a dlls/<key> folder beside the executable; and dlls/<key> in each of the six folders above it. Folders may not exist, and none is repeated. On Android only DeployedLibraryFolder is given, as the executable's path means nothing there.

Returns

The folders, without trailing delimiters.
