Description

Keeps a downloaded native library, such as OpenH264, up to date from an address given for each platform.

A JSON file names, for each platform key from Sprite3DNativeLibs, the address of the library to use: 

 {
   "win64": "https://example.com/openh264-2.6.0-win64.dll.bz2",
   "macarm": "",
   ...
 }

An empty or missing address means the library is not available on that platform. The library is downloaded into a folder of the caller's choosing, with a small installed.json beside it recording the address it came from. Creating a TSprite3DLibraryUpdate reads both files and nothing else: if the copy recorded was downloaded from the address now given, CurrentLibrary is its path straight away and no network is used. If the address has changed, as when 2.6.0 is replaced by 2.6.1, or the copy is missing, Start downloads the new one in the background, and once it has been checked it replaces the old copy, which is deleted then or, if it is still in use, the next time.

Downloads may be plain or compressed with bzip2 (.bz2, as Cisco publishes OpenH264) or gzip (.gz); the file is unpacked and checked to be a library for the platform: a Windows DLL, a Mach-O library or an ELF shared object. Any failure, a 404 or other HTTP error, no network, a timeout, a damaged download or something that is not a library, is reported as "not available" with the reason, and is tried again the next time the program starts.

Create, Start, Cancel and Free on the main thread; Start's procedure is called on the main thread too. Freeing the object cancels a download under way and waits for it to stop.
