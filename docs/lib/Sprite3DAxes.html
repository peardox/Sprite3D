Description

Draws a model's X, Y and Z axes through its centre of rotation.

ShowModelAxes adds a TModelAxes to a TGorillaModel. It shows three lines: red along X, green along Y and blue along Z. They cross at the model's centre of rotation, which is FMX's RotationCenter in the model's own coordinates and is the model's origin unless that has been changed. Each line runs from one face of the model's bounding box to the opposite face, so unless the centre of rotation lies outside that box, the lines stay inside the box that FitToBounds frames. The axes move, turn and scale with the model and show its own axes rather than the scene's. FMX's Y axis points down the screen, so with no rotation the green line's positive end is at the bottom.

There are two ways of drawing, chosen by OnTop. Gorilla's materials have no setting to turn depth testing off, so only the context can draw over the model.

OnTop True, the default, draws the lines over everything, so the model never hides them, even inside a solid model. In each frame's main pass the TModelAxes draws them with the context's DrawLine helper, following Gorilla v1.5's Line Rendering guide. Widths above 1 pixel work on desktop OpenGL only; Vulkan, Metal and OpenGL ES always draw 1 pixel.

OnTop False draws each line with a GLSL shader, through the documented SurfaceShader hook of a TGorillaDefaultMaterialSource, which Gorilla converts for Vulkan and Metal. Each line is drawn on two thin TGorillaPlane strips that cross along it, so it is seen from any angle; the shader keeps only the pixels within LineWidth / 2 of the strip's middle. The width works on every backend, except on macOS and iOS, where Gorilla3D's Metal backend does not support SurfaceShader: there each strip is a thin plane of the line's colour, its width a fraction of its length. The lines are ordinary geometry, so the model hides the parts inside it or behind it. The strips are not children of the model, so they never count in its bounding box; they sit in a frame beside the model that copies its position, rotation, scale and centre of rotation whenever they change. 

<model's parent>
|-- TGorillaModel
|   `-- TModelAxes          one per model, found by FindModelAxes; OnTop: draws the lines
|                           in its Render; otherwise keeps the frame on the model
`-- axes frame              OnTop False only; TDummy copying the model's transform
    `-- 6 x TGorillaPlane   two strips per line, drawn by their shaders

Usage: 

ShowModelAxes(GorillaModel1);                // after the model is loaded; drawn on top
ShowModelAxes(GorillaModel1, 2, False);       // shader lines 2 pixels wide
HideModelAxes(GorillaModel1);

function ShowModelAxes(const AModel: TGorillaModel; const ALineWidth: Single = 1; const AOnTop: Boolean = True): TModelAxes;

Draws AModel's X, Y and Z axes through its centre of rotation.

Any axes already on AModel are removed first, so calling it again, for example after loading a different model, redraws them for the new bounds. The lines cross at AModel.RotationCenter and each runs across AModel's current bounding box, from GetAnimatedBoundingBox, widened if need be to reach the centre of rotation. X is red, Y green and Z blue.

The axes are added as a child of AModel, so they follow its position, rotation and scale, and are freed with it. They are sized for the box at the time of the call. Without AOnTop, AModel must already have a parent. Call from the main thread only.

Parameters
AModel
The model to draw axes on. Nothing happens if it is nil.
ALineWidth
Line width in screen pixels. With AOnTop, values above 1 work on desktop OpenGL only; without it, on every backend.
AOnTop
True to draw the lines over everything, so the model cannot hide them; False to draw them with shaders, letting the model hide the parts inside it.
Returns

The new axes, owned by AModel; or nil, with nothing added, if AModel is nil or its bounding box is empty.
