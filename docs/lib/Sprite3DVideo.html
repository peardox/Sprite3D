Description

Writes a sequence of frames as a video-only MP4 file with the FFmpeg libraries, loaded only when first needed.

SaveMp4Video writes H.264 when Cisco's OpenH264 library is present, through Sprite3DOpenH264, and MPEG-4 Part 2 otherwise. H.264 plays everywhere, web browsers included. MPEG-4 Part 2 is FFmpeg's own mpeg4 encoder, which every FFmpeg build has and which needs no library beyond FFmpeg's own under its LGPL licence; it plays in desktop players such as VLC, QuickTime and the Windows players, but not in web browsers. In both cases FFmpeg writes the MP4 file, and there is no sound track. OpenH264 is used only as Sprite3DOpenH264 is told, from the copy downloaded for the platform.

The unit does not use the DelphiFFmpeg.com FFmpeg 8.1 headers in the ffmpeg folder. Those bind every function statically: the linker is given every library they name, so on macOS and iOS the program would not link, or not start, without the libraries, and they define some error codes only for Windows and macOS, so they do not compile for Linux or Android. Instead the few records and constants it needs are declared privately in the implementation section, copied field for field from those headers, and it loads avutil, avcodec and avformat itself with LoadLibrary or dlopen and looks up the two dozen functions it needs, with the headers' signatures. So Sprite3D builds for every platform, starts and runs whether or not the libraries are there, and offers video only when VideoAvailable says they loaded.

The libraries must be FFmpeg 8.1's major versions, as the headers are: avutil 60, avcodec 62 and avformat 62. They are looked for in the folders NativeLibraryFolders in Sprite3DNativeLibs gives, first the platform's usual place for an application's own libraries, then a dlls/<platform> folder beside the executable or above it, and last wherever the system looks for libraries. 

Windows     avutil-60.dll         avcodec-62.dll         avformat-62.dll
macOS, iOS  libavutil.60.dylib    libavcodec.62.dylib    libavformat.62.dylib
Linux       libavutil.so.60       libavcodec.so.62       libavformat.so.62
Android     libavutil.so          libavcodec.so          libavformat.so

Android only unpacks libraries named lib*.so from an APK, so there the names have no version.

Any other FFmpeg library one of those needs, such as swresample, must be in the same folder; it is loaded first if it is there.

For the main thread, or any one thread at a time.

function VideoAvailable: Boolean;

Whether MP4 video can be written: the FFmpeg libraries loaded and have the encoder.

The first call looks for and loads the libraries, which takes a moment; later calls return the same answer at once. The libraries stay loaded until the program ends.

Returns

True if SaveMpeg4Video can be used.

function VideoStatus: String;

Why video is or is not available, for a log or a hint.

Loads the libraries if VideoAvailable has not yet been called.

Returns

Where the libraries were loaded from and their versions, or what was missing, with a second line saying whether OpenH264 was found.

procedure SaveMpeg4Video(const AFrames: TArray<TSprite3DImage>; const AFileName: String; const ACycleSeconds: Double);

Writes the frames as a video-only MPEG-4 Part 2 MP4 file.

One cycle of ACycleSeconds is shown as Length(AFrames) equal frames, so the video lasts exactly one cycle; the frame rate is carried as an exact fraction where it can be. MP4 has no transparency, so each frame is laid over black, which a Solid or Gradient background will already have covered. The width and height are rounded up to even numbers, as the encoder's colour format needs, with black in the extra row or column. Quality is fixed and high (quantiser 3), every twelfth frame is a key frame and there are no B-frames. The file replaces any of that name; the folder must exist. Blocks while it encodes.

Parameters
AFrames
The frames, in order; at least one, all the same size.
AFileName
The file to write, normally ending in .mp4.
ACycleSeconds
How long all the frames last together, in seconds; more than 0.
Exceptions raised
ESprite3DVideoError
If the libraries are not available, or FFmpeg fails at any step; a part-written file may be left behind.
EArgumentException
If there are no frames, they differ in size, or ACycleSeconds is not more than 0.
function H264Available: Boolean;

Whether MP4 video will be H.264: FFmpeg and OpenH264 both loaded.

Loads the libraries if VideoAvailable has not yet been called.

Returns

True if SaveMp4Video writes H.264; False if it writes MPEG-4 Part 2, or nothing.

function RecheckH264: Boolean;

Looks for OpenH264 again, after a copy may have been added, unless one is loaded.

For when OpenH264 has been downloaded while the program runs; tell Sprite3DOpenH264 where with SetPreferredOpenH264 first. A copy already loaded stays in use until the program ends, as a loaded library cannot be swapped safely.

Returns

True if H.264 is available now.

procedure SaveH264Video(const AFrames: TArray<TSprite3DImage>; const AFileName: String; const ACycleSeconds: Double);

Writes the frames as a video-only H.264 MP4 file with OpenH264.

As SaveMpeg4Video in every way but the codec: H.264 Constrained Baseline from OpenH264, aiming at a constant quality with about a quarter of a bit per pixel per frame and never dropping a frame, a key frame every twelfth frame, no B-frames. The width and height must reach 16 pixels after rounding up to even numbers.

Parameters
AFrames
The frames, in order; at least one, all the same size.
AFileName
The file to write, normally ending in .mp4.
ACycleSeconds
How long all the frames last together, in seconds; more than 0.
Exceptions raised
ESprite3DVideoError
If FFmpeg is not available, or FFmpeg fails at any step; a part-written file may be left behind.
ESprite3DH264Error
If OpenH264 is not available or fails.
EArgumentException
If there are no frames, they differ in size, or ACycleSeconds is not more than 0.
function SaveMp4Video(const AFrames: TArray<TSprite3DImage>; const AFileName: String; const ACycleSeconds: Double): String;

Writes the frames as a video-only MP4 file, H.264 if it can, else MPEG-4 Part 2.

Uses SaveH264Video when H264Available, and SaveMpeg4Video otherwise; see those for the details. Frames that would be smaller than 16 pixels across or down are always MPEG-4 Part 2, as OpenH264 cannot take them. If OpenH264 itself fails, the file is written again as MPEG-4 Part 2, and the result says why.

Parameters
AFrames
The frames, in order; at least one, all the same size.
AFileName
The file to write, normally ending in .mp4.
ACycleSeconds
How long all the frames last together, in seconds; more than 0.
Returns

The codec written, 'H.264' or 'MPEG-4 Part 2', with the reason after it if H.264 was tried and failed, for a log.

Exceptions raised
ESprite3DVideoError
If FFmpeg is not available or fails.
EArgumentException
If there are no frames, they differ in size, or ACycleSeconds is not more than 0.
