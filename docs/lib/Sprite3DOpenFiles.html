Description

Collects the files the operating system asks the application to open.

When the user opens a document with an application, for example by double-clicking a file associated with it, each platform tells the application differently. This unit gathers them into one place, FileOpenRequests, so the application handles them the same way everywhere.

Requests that arrive before the application is ready wait in a queue; TakePending returns them, and from then on each new request is passed straight to OnOpenFile, if it is set. All requests are reported on the main thread, as full paths of local files.

The unit knows nothing of any particular file type; filtering is the caller's job. Registering the file types with the operating system is also the caller's: a file association on Windows, a .desktop file on Linux, document types in Info.plist on macOS and iOS, and an intent filter in AndroidManifest.xml on Android. 

Windows   command line: Explorer starts the program with the file's full path
Linux     command line: Exec=... %f in the .desktop file
macOS     the "open documents" Apple event from Finder or the Dock, at launch and later;
          also the command line, when started with a file name
iOS       the open-URL application event, at launch and later
Android   the VIEW intent that started the activity, and any later one; content:// files
          are copied into the application's cache folder first
