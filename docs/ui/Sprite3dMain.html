Description

Demo form for TSprite3DCamera: loads a model and drives the camera with dials.

The form has two tabs. The View tab holds a TGorillaViewport, created at run time, and a panel of three dials for Azimuth, inclination and Roll. The Debug tab holds a memo for log output. Below the Camera submenu, the View menu has six items that are ticked or not, each switched by choosing it: Show bounding box shows the model's bounding box, Show grid a grid on the model's floor, Show axes its own X, Y and Z axes through its centre of rotation, Show Model Volume the space it sweeps turning about its up axis in the animation playing, Show Animation Volume the one joined over the rest pose and every animation used, shown only while it is the volume the view frames, and Orthographic switches between perspective and orthographic projection. Model, Animations Used chooses which of the model's animations are listed and count towards the combined swept volume.

The camera starts in the isometric view, and each readout always shows its dial's angle, from 0 to 359 degrees. Azimuth is sent to the camera reversed, 360 minus the readout, so the view turns the right way for the dial. View, Camera, Variable lets the dials set the angles; View, Camera, Isometric, the default for now, sets the readouts to inclination 35.264, azimuth 45 and roll 0, the true isometric view, and switches the dials off; View, Camera, Pixel 2:1 does the same with an inclination of about 26.565; View, Camera, 1/4 View, 3/4 View, Sqrt(2) and Golden Ratio use about 22.5, 45, 54.736 and 58.283; View, Camera, Head On and View, Camera, Top Down use inclinations of 0 and 90 at azimuth 0; and View, Camera, Side View uses inclination 0 at azimuth 90. A test slider along the bottom of the 3D view moves the camera out from the fitted distance, x1 to x20.

A model is loaded behind a modal dialog, TModelLoadForm, with a progress bar, a line saying what is happening, and Abort. The file is read on a worker thread; Gorilla3D then builds the model from it in one step, which cannot be interrupted; and each animation's bounds, which the volumes and the fit need, are measured a slice at a time, unless they are in the bounds folder of the application's support folder from an earlier load of the same, unchanged file. The new model is built beside the one shown, which is left alone until the new one is ready, so Abort, or a failure, leaves the previous model, or none at start-up. While there is no model, a panel over the view says how to load one. The window is drawn before the first model loads, the video libraries are looked for only once that load has ended, and saved files are composed and encoded on a worker thread.

On show, the form loads the model the operating system asked it to open, as when a .glb or .gltf file is double-clicked in Explorer or Finder, or else what the start-up action in File, Settings asks for; files the system asks to open later replace it. File, Open Model then loads any other glTF, FBX, OBJ, USD, Collada, STL or PLY file, and File, Exit closes the application. File, Grab renders the view off screen at the grab size set in File, Settings, 256 by 256 pixels unless changed, with the model fitted to fill it, and saves it as the next of grab001.png, grab002.png and so on in SaveFolder, asking for that folder only when none is known: SaveFolder is kept between sessions in settings.json, through TSprite3DAppSettings in Sprite3DHelpers. File, Save As Icon renders the view off screen at each of Windows' icon sizes and saves them together as one .ico file the user names. Behind the model the viewport can show a background; by default none is drawn. File, Background Settings... chooses None, Transparent (a two-grey checker standing for transparency), Solid or Gradient, which grabs and icons follow too.

File, Settings... opens TGeneralSettingsForm, centred on this form: whether Sprite3D is offered under Open With for model files and whether it is their default application, the start-up action (no model, the sample model or the model last opened), the size of off-screen grabs (a square preset from 8 to 512 pixels, or a custom width and height from 8 to 1024), the theme (FMX's default style, Dark, or the coloured Aqua, Ruby and Golden Graphite styles, which the title bars follow where the system allows) and, on Windows, which GPU to ask for, which takes effect at the next start. All are kept in settings.json.

The Variable camera dialog can also pan the view along the model's own X and Z axes, for the odd model that should sit off centre. The pan moves the point the camera orbits, on top of every fit, on screen and in grabs and icons, in whichever view is chosen, until it is switched off; it never changes the angles or the distance. It is off by default and kept in settings.json.

The Animations list shows, to the right of each entry under the Frames title, how many frames saving it makes at the Model, Animation Settings frame rate: the animation's length times the rate, rounded, or 1 for (None), a single still frame. Model, Animations Used opens a dialog that ticks which animations are used; the others are left out of the list, so they are not played, saved or exported, and out of the combined swept volume. A new model starts with every animation used.

Under the list, five buttons with icons, named in their hints, act on the selected animation: first frame, previous frame, play or pause, next frame and last frame. The frames are those an export makes at the Model, Animation Settings frame rate, held exactly as the export shows them, by TSprite3DAnimationPlayer; any of the four frame buttons pauses the animation on its frame. After them, a readout always shows the frame showing, held or playing, and the frames in all, with the "/" in a fixed place; it reads "- / -" when there is no animation to count, as for (None). A readout over the top left of the view, white on a dark backing, shows the frames per second the viewport draws, which File, Settings sets, kept within the refresh rate of the display the window is on, and checked again whenever the window moves to another display. Play and pause share a button, whose icon and hint change to say which it does. Stepping wraps round from the last frame to the first and back. Choosing an entry plays it from the start, unless the controls are paused, when it starts paused on its first frame; starting a capture lets a held animation play on. Grabs and icons are saved as the view shows them, with the background and every helper showing. Animation exports show the model alone: the bounding box, axes, grid and volume wireframes are hidden for each drawing, and the background is left out, so they are transparent around the model, or black for MP4.

Right-clicking an entry in the Animations list selects and plays it, and opens a pop-up menu with Save as sprite strip, Save as Spritesheet, Save as AniGif and Save as MP4 video. Each grabs every frame of that animation off screen, from the first to the last, at the grab size and with one framing that fits every frame, and saves them in SaveFolder: side by side in one row as <animation>_strip<frames>.png, in a square grid read left to right and top to bottom as <animation>.png, as a looping <animation>.gif, or as a video-only <animation>.mp4 through Sprite3DVideo, H.264 when Cisco's OpenH264 library is present and MPEG-4 Part 2 otherwise. MP4 is offered only when the FFmpeg libraries load; DebugMemo says at start-up whether they did and from where. The (None) entry, which has no animation, captures instead a single still frame of the model in its bind pose, named after the model. On Android and iOS, which have no right-click, the same items are in an Animation group of the menu drawer and act on the selected entry.

At start-up the OpenH264 library, which makes MP4 files H.264, is taken from openh264.json: an address for each platform, from which a copy is downloaded in the background into OpenH264Folder the first time, and again whenever the address changes. An empty address, or a failed download, leaves MP4 files as MPEG-4 Part 2. DebugMemo says which happened.

Model, Animation Settings... sets the frame rate every saved animation uses, 30 frames a second unless changed, from 1 to 60, kept in settings.json. Each animation is resampled to it: one cycle is cut into the whole number of equal steps nearest that rate, so the saved frames still loop exactly; see TSprite3DAnimationFrames. The same dialog turns overscan on, for this session only: every grab, icon and export is drawn 2 to 16 times larger each way, as far as the GPU allows at the grab size, and scaled down with the resampling filter chosen there, by TSprite3DOffscreen. The factor and filter are kept in settings.json.

Each entry also has a tick box. Below the list, All ticks every animation, leaving (None) as it is so the turn is exported only when ticked by hand, or clears every entry; a drop-down chooses Sprite strip, Spritesheet, Texture Atlas, AniGif or, when FFmpeg loaded, MP4 video, and Export saves every ticked entry that way, one after another, in a folder chosen in a folder dialog that opens at SaveFolder, so a new sub-folder can be made there for the batch. SaveFolder itself is not changed. A failed entry is reported at the end and does not stop the others. Each entry is unticked as soon as it is saved, so a failed one stays ticked for another try. Abort, enabled only while a batch runs, lets the entry being captured finish and save, then drops the rest. On Android and iOS, which have no folder dialog, the batch goes to the Grabs folder.

The drop-down's Texture Atlas asks for its folder as it is chosen. Its batch captures every ticked entry, then packs them, in list order, onto pages no larger than the page size in Model, Animation Settings, saved as <model>_atlas_01.png, _02 and so on; see SaveAtlas.

View, Camera, Lock Camera fixes the camera where it is. While it is ticked nothing moves or turns the camera: the views, Orthographic and the pan are switched off, a new model or a resized view is not refitted, and grabs, icons and animation captures use the view exactly as it stands instead of fitting the model to their own size. The lock is not kept between sessions.

Each model replaces the last: it is centred and turned 180 degrees about X, and the camera is fitted so it fills the view. The model is refitted when the viewport is resized, the projection changes, the animations used change, another entry is chosen, an entry is ticked or unticked for export, or an animation is paused, stepped or played, but not when a dial turns. While two or more animations are ticked, playing or paused, the fit frames the combined swept volume, the space the model sweeps turning about its up axis over its rest pose and every animation used, so everything a batch exports is framed alike, and Show Animation Volume draws it. Otherwise, with one ticked or none, as for a model without animations, it frames the volume of what is on screen alone: the selected animation's, paused or playing, or the rest pose's for (None). Either way the volume fills the view on the tighter axis, and the orbit centre is on the turning axis, so turning the azimuth dial keeps the model in view.

The form only handles the user interface. The 3D work is done by the library units in lib: Sprite3DCamera, Sprite3DAxes, Sprite3DGrid, Sprite3DSweep and Sprite3DOffscreen. The application's other rules, such as where models are found, how a model is loaded and placed, and how grabs are named and saved, are in Sprite3DHelpers.

On Android and iOS, where FMX shows no menu bar, the same menus are reached through a hamburger button on a toolbar at the top, which opens a drawer listing every item in MainMenu1; ticks show the current camera view and which View items are on. Exit is left out on iOS. On Linux the same items are moved onto a TMenuBar that FMX draws itself, as the native GTK menu bar showed only the first letter of each item.

Types

TSheetKind = (...);

What the animation list's pop-up menu saves a capture as.

Values
  • skStrip: One row of frames, saved as <name>_strip<count>.png.
  • skSheet: A square grid of frames, saved as <name>.png.
  • skAtlas: Texture atlas pages: every animation of a batch packed onto shared pages, saved as <model>_atlas_01.png and so on; batch Export only.
  • skGif: A looping animated GIF, saved as <name>.gif.
  • skMp4: A video-only MPEG-4 MP4, saved as <name>.mp4; only offered when the FFmpeg libraries load.
TModelLoadStage = (...);

Where a model load has got to; see TMainForm.SwitchModel.

Values
  • lsNone: No load is under way.
  • lsRead: The file is being read on a worker thread; Abort stops it at once.
  • lsBuild: Gorilla3D builds the model on the next tick, in one step.
  • lsMeasure: The new model's animations are being measured, a slice at a time.
  • lsCommit: The new model replaces the old one on the next tick.
