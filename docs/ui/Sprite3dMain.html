Description

Demo form for TSprite3DCamera: loads a model and drives the camera with dials.

The form has two tabs. The View tab holds a TGorillaViewport, created at run time, and a panel of three dials for Azimuth, inclination and Roll. The Debug tab holds a memo for log output. Below the Camera submenu, the View menu has five items that are ticked or not, each switched by choosing it: Show bounding box shows the model's bounding box, Show grid a grid on the model's floor, Show axes its own X, Y and Z axes through its centre of rotation, Fit any angle chooses how the model is fitted, and Orthographic switches between perspective and orthographic projection.

The camera starts in the isometric view, and each readout always shows its dial's angle, from 0 to 359 degrees. Azimuth is sent to the camera reversed, 360 minus the readout, so the view turns the right way for the dial. View, Camera, Variable lets the dials set the angles; View, Camera, Isometric, the default for now, sets the readouts to inclination 35.264, azimuth 45 and roll 0, the true isometric view, and switches the dials off; View, Camera, Pixel 2:1 does the same with an inclination of about 26.565; View, Camera, 1/4 View, 3/4 View, Sqrt(2) and Golden Ratio use about 22.5, 45, 54.736 and 58.283; View, Camera, Head On and View, Camera, Top Down use inclinations of 0 and 90 at azimuth 0; and View, Camera, Side View uses inclination 0 at azimuth 90. A test slider along the bottom of the 3D view moves the camera out from the fitted distance, x1 to x20.

On show, the form loads the model the operating system asked it to open, as when a .glb or .gltf file is double-clicked in Explorer or Finder, or else what the start-up action in File, Settings asks for; files the system asks to open later replace it. File, OpenModel then loads any other glTF, FBX, OBJ, USD, Collada, STL or PLY file, and File, Exit closes the application. File, Grab renders the view off screen at the grab size set in File, Settings, 256 by 256 pixels unless changed, with the model fitted to fill it, and saves it as the next of grab001.png, grab002.png and so on in SaveFolder, asking for that folder only when none is known: SaveFolder is kept between sessions in settings.json, through TSprite3DAppSettings in Sprite3DHelpers. File, Save As Icon renders the view off screen at each of Windows' icon sizes and saves them together as one .ico file the user names. Behind the model the viewport can show a background; by default none is drawn. File, Background Settings... chooses None, Transparent (a two-grey checker standing for transparency), Solid or Gradient, which grabs and icons follow too.

File, Settings... opens TGeneralSettingsForm, centred on this form: whether Sprite3D is offered under Open With for model files and whether it is their default application, the start-up action (no model, the sample model or the model last opened), the size of off-screen grabs (a square preset from 8 to 512 pixels, or a custom width and height from 8 to 1024), the theme (FMX's default style, Dark, or the coloured Aqua, Ruby and Golden Graphite styles, which the title bars follow where the system allows) and, on Windows, which GPU to ask for, which takes effect at the next start. All are kept in settings.json.

The Variable camera dialog can also pan the view along the model's own X and Z axes, for the odd model that should sit off centre. The pan moves the point the camera orbits, on top of every fit, on screen and in grabs and icons, in whichever view is chosen, until it is switched off; it never changes the angles or the distance. It is off by default and kept in settings.json.

Right-clicking an entry in the Animations list selects and plays it, and opens a pop-up menu with Save as sprite strip, Save as Texture Atlas, Save as AniGif and Save as MP4 video. Each grabs every frame of that animation off screen, from the first to the last, at the grab size and with one framing that fits every frame, and saves them in SaveFolder: side by side in one row as <animation>_strip<frames>.png, in a square grid read left to right and top to bottom as <animation>.png, as a looping <animation>.gif, or as a video-only <animation>.mp4 through Sprite3DVideo, H.264 when Cisco's OpenH264 library is present and MPEG-4 Part 2 otherwise. MP4 is offered only when the FFmpeg libraries load; DebugMemo says at start-up whether they did and from where. The (None) entry, which has no animation, captures instead one full turn of the model in one second, at the File, Animation frame rate, named after the model with _rotate added. On Android and iOS, which have no right-click, the same items are in an Animation group of the menu drawer and act on the selected entry.

At start-up the OpenH264 library, which makes MP4 files H.264, is taken from openh264.json: an address for each platform, from which a copy is downloaded in the background into OpenH264Folder the first time, and again whenever the address changes. An empty address, or a failed download, leaves MP4 files as MPEG-4 Part 2. DebugMemo says which happened.

File, Animation... sets the frame rate every saved animation uses, 30 frames a second unless changed, from 1 to 60, kept in settings.json. Each animation is resampled to it: one cycle is cut into the whole number of equal steps nearest that rate, so the saved frames still loop exactly; see TSprite3DAnimationFrames.

Each entry also has a tick box. Below the list, All ticks every animation, leaving (None) as it is so the turn is exported only when ticked by hand, or clears every entry; a drop-down chooses Sprite strip, Texture Atlas, AniGif or, when FFmpeg loaded, MP4 video, and Export saves every ticked entry that way, one after another, in a folder chosen in a folder dialog that opens at SaveFolder, so a new sub-folder can be made there for the batch. SaveFolder itself is not changed. A failed entry is reported at the end and does not stop the others. Each entry is unticked as soon as it is saved, so a failed one stays ticked for another try. Abort, enabled only while a batch runs, lets the entry being captured finish and save, then drops the rest. On Android and iOS, which have no folder dialog, the batch goes to the Grabs folder.

View, Camera, Lock Camera fixes the camera where it is. While it is ticked nothing moves or turns the camera: the views, Orthographic, Fit any angle and the pan are switched off, a new model or a resized view is not refitted, and grabs, icons and animation captures use the view exactly as it stands instead of fitting the model to their own size. The (None) turn cannot be captured while it is locked, as it turns the camera. The lock is not kept between sessions.

Each model replaces the last: it plays its last animation by name if it has any, is centred and turned 180 degrees about X, and the camera is fitted so it fills the view. The model is refitted when the viewport is resized, the projection changes or View, Fit any angle is chosen, but not when a dial turns. Ticked, that item uses FitToBoundsMax, which frames the model for every angle at once, so the dials can never push it out of view. Not ticked, FitToBounds frames it exactly for the angles at the time of the fit, and turning a dial afterwards can push part of it past the edge until the next refit.

The form only handles the user interface. The 3D work is done by the library units in lib: Sprite3DCamera, Sprite3DAxes, Sprite3DGrid and Sprite3DOffscreen. The application's other rules, such as where models are found, how a model is loaded and placed, and how grabs are named and saved, are in Sprite3DHelpers.

On Android and iOS, where FMX shows no menu bar, the same menus are reached through a hamburger button on a toolbar at the top, which opens a drawer listing every item in MainMenu1; ticks show the current camera view and which View items are on. Exit is left out on iOS. On Linux the same items are moved onto a TMenuBar that FMX draws itself, as the native GTK menu bar showed only the first letter of each item.

TSheetKind = (...);

What the animation list's pop-up menu saves a capture as.

Values
  • skStrip: One row of frames, saved as <name>_strip<count>.png.
  • skAtlas: A square grid of frames, saved as <name>.png.
  • skGif: A looping animated GIF, saved as <name>.gif.
  • skMp4: A video-only MPEG-4 MP4, saved as <name>.mp4; only offered when the FFmpeg libraries load.
