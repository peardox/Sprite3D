Unit

Sprite3dMain

Declaration

type TMainForm = class(TForm)

Description

The main form: a Gorilla3D view of one model, with dials for the camera.

The viewport, light, model and TSprite3DCamera are created at run time, not at design time; the form owns none of them directly. All event handlers run on the main thread.

Methods

Public procedure FormCreate(Sender: TObject);

Sets up the viewport, light and camera, and picks the models folder.

The models folder comes from DefaultModelDir in Sprite3DHelpers: it is the library path on macOS, the home folder on Linux and '../../../' elsewhere; on Windows it is the current folder instead if that has a models subfolder. The handler creates a TGorillaViewport owned by ViewportLayout, a TSprite3DCamera with a 45-degree FOV, which becomes the viewport's camera, and a point light parented to the camera at its origin, so it sits where the camera is and points where it looks. The viewport runs at a fixed 60 frames per second without VSync.

The dials start at 0, then the camera view kept in settings.json is chosen, as its View, Camera item would choose it: a fixed view turns the dials to its angles and switches them off, and Variable turns them to the angles kept with it and leaves them on. Isometric is chosen when none is kept. Last, the View menu's five on/off items are ticked as settings.json says they were left, and applied, which also sets the projection.

The form.
Public procedure FormShow(Sender: TObject);

Loads the first model, the one the system asked to open or the default, and starts taking open requests.

If the application was started to open a model, for example by double-clicking a .glb or .gltf file in Explorer or Finder, that model is loaded; the files come from FileOpenRequests in Sprite3DOpenFiles, and the first one that is a model is used. Otherwise the default model, named in this handler, is loaded; change it there to start with a different one. From then on, files the system asks to open while the application runs, as macOS, iOS and Android can, replace the current model. Runs once, the first time the form is shown. Shows a message and loads nothing if the file is missing or cannot be read.

Parameters
Sender
The form.
Public procedure FormDestroy(Sender: TObject);

Stops taking open requests, saves the view state and frees the settings.

The checked View, Camera item, the dials' angles if that is Variable, and the ticks of the View menu's five on/off items are written to settings.json for the next session; a failed save is ignored, as no message can be shown here. Other settings are saved as soon as they change.

The dial value is negated, wrapped into 0 to 360 and shown in AzimuthText. The camera gets the angle reversed, 360 minus the readout, so the view turns the right way for the dial. The model is not refitted; see FitAnyAngleItem.

Public procedure OpenModelMenuItemClick(Sender: TObject);

Lets the user pick a model file and loads it in place of the current one.

Shows OpenDialog1 and passes the chosen file to SwitchModel, which clears the old model and loads the new one with the current camera angles and fit mode. Nothing changes if the dialog is cancelled. A file that fails to load is reported by SwitchModel, and the view is then left empty until another model loads.

Public procedure GrabMenuItemClick(Sender: TObject);

Renders the view off screen and saves it as the next grabNNN.png.

If no usable SaveFolder is known, because none has been chosen yet or the stored one no longer exists, a "Save Location" folder dialog asks for it first, and SaveFolder is set to the choice and saved; if the dialog is cancelled nothing is grabbed. The image comes from Offscreen at its Width and Height, 256 by 256 unless changed, with the camera refitted by FitToBounds for that size so the model fills it, and is saved a frame later as grab001.png, grab002.png and so on: the number starts at 1 when the folder is chosen and goes up by one for every file saved, skipping any name already in the folder, so earlier grabs are never overwritten. Each saved file is logged in DebugMemo; a failed grab or save is reported with a message. A click while the previous grab is still under way is ignored.

Public procedure SaveAsIconMenuItemClick(Sender: TObject);

Renders the view at every icon size and saves it as one icon file.

First asks for the file with SaveIconDialog, which opens in the folder the last icon was saved in, kept in settings.json, and offers only the .ico type; nothing happens if it is cancelled. Android and iOS have no save dialog, so there the icon goes to the next free iconNNN.ico in the Grabs folder. Then Offscreen renders the view once for each of the format's sizes, 16, 20, 24, 32, 40, 48, 64 and 256 for .ico, each with the camera fitted to it as for File, Grab, and the images are written together. The saved file is logged in DebugMemo; a failure is reported with a message. A click while a grab is under way is ignored.

Public procedure BackgroundSettingsMenuItemClick(Sender: TObject);

Opens the Background Settings dialog and applies what is chosen.

The dialog, TBackgroundSettingsForm, opens modally, centred on this form, showing the background in use. If it is closed with OK, the chosen background is shown in the viewport, used for grabs and icons, and saved to settings.json; Cancel changes nothing. Public procedure ViewIsometricItemClick(Sender: TObject);

Sets the isometric view and fixes it.

Clears every View check, sets the inclination to ArcTan(1/Sqrt(2)), about 35.264 degrees, the true isometric elevation, the azimuth to 45 and the roll to 0, as shown on the readouts, turns the dials to match and switches them off, refits the model for the new view, then checks the Isometric item. As with the dial, the azimuth reaches the camera reversed. The other fixed views work the same way with their own inclination.

Properties

Public property SaveFolder: String read GetSaveFolder write SetSaveFolder;

The folder File, Grab saves into, kept between sessions; empty until one is chosen.

Read from settings.json at start-up, so it is empty only on the first run, or until a folder is chosen. The first grab without a usable folder shows the "Save Location" dialog and stores the choice here. Android and iOS have no such dialog: there the first grab sets it to a Grabs folder in the app's public storage on Android, or its Documents folder on iOS. Setting it saves settings.json at once; a failure to write the file is reported with a message, and the new folder is still used this session. Set it to empty to be asked again.

Public property Offscreen: TSprite3DOffscreen read FOffscreen;

The off-screen renderer File, Grab uses; set its Width and Height to change the grab size.

Created in FormCreate, attached to the viewport, which owns and frees it.
