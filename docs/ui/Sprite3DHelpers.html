Description

Support routines for the Sprite3D application that are neither UI nor library.

The application keeps three kinds of code apart. The units in ui only handle the user interface; the units in lib are a library with no knowledge of this application, usable in other projects; and this unit holds what is left: the application's own rules, such as where models are found, how grabs are named and saved, and how a loaded model is placed. It uses the library and the RTL, never the UI.

TSprite3DAppSettings holds the settings kept between sessions, in settings.json in the application's own per-user folder, SupportFolder. The measured bounds of each model's animations are kept there too, one file per model in its bounds folder, through LoadAnimationBoundsCache and SaveAnimationBoundsCache.

Loading a model through LoadModelFile also registers Gorilla3D's loaders for glTF, FBX, OBJ, USD, Collada, STL and PLY files, as this unit uses them.

All routines are for the main thread, except the members of IModelFileRead.

function CompassPointName(const ADegrees: Single): String;

The abbreviated name of a point of the 32-point compass, if a bearing is on one.

The points are 11.25 degrees apart, named as the mariner's compass names them: the cardinal points N, E, S and W; the intercardinal NE, SE, SW and NW; the eight winds between them, NNE, ENE and so on; and the sixteen "by" points, NbE (north by east), NEbN and so on.

Parameters
ADegrees
A bearing in degrees clockwise from north, any number of turns.
Returns

The point's abbreviation, such as N, NbE, NNE or NEbN, for a bearing within a hundredth of a degree of one; otherwise an empty string, so a whole-degree bearing only has a name on the eight points that fall on whole degrees.

procedure SaveDirectionsFile(const AFileName: String; const ACount: Integer; const AStart: Single; const AOrder: TArray<Integer>; const ASnap: Boolean);

Writes a set of directions to a JSON file, for Model, Directions' Export.

The file holds everything Model, Directions sets, so it can be read back with LoadDirectionsFile, kept beside artwork whose directions come in a fixed order, and swapped between models: 

 {
   "format": "Sprite3D directions",
   "version": 1,
   "count": 8,
   "start": 0,
   "snap": false,
   "clockwise": true,
   "order": [3, 5, 7, 1, 4, 6, 8, 2],
   "directions": [
     { "number": 1, "position": 3, "bearing": 90, "point": "E" },
     ...
   ]
 }

order holds the positions, counted clockwise from 1 at the red marker, in the order the directions are taken in, as DirectionOrder does. directions spells each one out, with its bearing and compass point, for people and other tools to read; LoadDirectionsFile ignores it. The folder is made if it does not exist.

Parameters
AFileName
The file to write; replaced if it exists.
ACount
How many directions; one of DIRECTION_COUNTS.
AStart
The red marker's bearing, in degrees clockwise from north.
AOrder
The order, as positions from 0; one that does not fit ACount is written as the plain clockwise order.
ASnap
Whether the dial is locked to steps of one direction.
Exceptions raised
EInOutError
or another file exception if the file cannot be written.
procedure LoadDirectionsFile(const AFileName: String; out ACount: Integer; out AStart: Single; out AOrder: TArray<Integer>; out ASnap: Boolean);

Reads a set of directions from a JSON file written by SaveDirectionsFile.

count and start are needed. order may be left out, when clockwise, true if it too is left out, gives the plain order; snap may be left out, for False. format, when present, must be DIRECTIONS_FILE_FORMAT, and version, when present, no newer than DIRECTIONS_FILE_VERSION. Anything else in the file is ignored.

Parameters
AFileName
The file to read.
ACount
Set to the number of directions, one of DIRECTION_COUNTS.
AStart
Set to the red marker's bearing, wrapped into 0 up to 360.
AOrder
Set to the order, as positions from 0, every one once.
ASnap
Set to whether the dial is locked to steps of one direction.
Exceptions raised
EDirectionsFile
if the file is not JSON, is not a directions file, or holds a count or order that cannot be used; the message says which, for showing as it is.
EFileNotFoundException
or another file exception if the file cannot be read.

function StartModelFileRead(const AFileName: String): IModelFileRead;

Starts reading a model file from start to end on a worker thread.

Nothing is kept: the point is to bring the file into the operating system's file cache, which is where a cold load spends most of its time, while the user interface goes on and the read can be cancelled; Gorilla3D's own load, which cannot, then finds it there. The file is read in blocks of a megabyte, shared for reading and writing.

Parameters
AFileName
The file to read.
Returns

The read under way.

function ModelPanOffset(const AModel: TGorillaModel; const ABox: TBoundingBox; const APanX, APanZ: Single): TPoint3D;

How far to move the orbit centre for a camera pan.

The pan runs along the model's own X and Z axes, as View, Show axes draws them, so it never moves the view up or down the model's Y axis. Each amount is a multiple of the model's radius, half the diagonal of ABox, so a pan looks the same for a model of any size. The camera's angles and distance are not involved.

Parameters
AModel
The model; nil gives no offset.
ABox
The model's own bounds as loaded, for its size.
APanX
The pan along the model's X axis; limited to PAN_LIMIT either way.
APanZ
The pan along the model's Z axis; limited to PAN_LIMIT either way.
Returns

The offset to add to the fitted orbit centre, in the viewport's space.

function ApplyTheme(const ATheme: TSprite3DTheme; out AError: String): Boolean;

Gives the whole application, title bars included, the look ATheme names.

thDefault puts back FMX's own platform style and the system's title bars. The other themes are the FMX styles that come with RAD Studio: Dark.style, AquaGraphite.style, RubyGraphite.style and GoldenGraphite.style. Each is looked for as a linked-in RCDATA resource called Sprite3D<Name>Style, such as Sprite3DDarkStyle, which styles\Sprite3DThemes.rc links into every build, then, should that be missing, as a file in a styles folder beside the program or its assets, beside the program, in a styles folder in SupportFolder, or, on Windows, in RAD Studio's Redist\styles\Fmx folder when the BDS environment variable is set, as it is when run from the IDE. Once the style is in use, the title bars take its form background colour, with the theme's accent as the window border, where the system allows; see Sprite3DTitleBar.

Parameters
ATheme
The look to use.
AError
On failure, why, including where it looked.
Returns

True if the look is now in use; False leaves the current one, title bars included.

function ApplyFileAssociations(const ASettings: TSprite3DAppSettings; const AOpenWith, AAlways: Boolean; out AMessage: String): Boolean;

Registers or unregisters the application for model files as asked, keeping what is needed to undo it in ASettings.

In order: registers for Open With if AOpenWith; makes the application the default if AAlways, recording the old defaults in ASettings.AssociationBackup, or otherwise puts back the recorded defaults if it was the default; and unregisters if not AOpenWith. AAlways counts only with AOpenWith, except on macOS, where Open With is fixed by the bundle. Where the user has to confirm a default in the system's own settings, that page is opened and AMessage says so. ASettings.OpenWith and AlwaysOpenWith are updated to the result; the caller saves ASettings.

Parameters
ASettings
The application's settings, for the backup.
AOpenWith
Whether to be offered under Open With.
AAlways
Whether to be the default for model files.
AMessage
Anything the user should be told, failures included; empty if nothing.
Returns

True if every step succeeded.

function RegisterProjectFiles(out AMessage: String): Boolean;

Makes Sprite3D open its own project files, PROJECT_FILE_EXTENSION, when one is double-clicked.

Called each time the application starts, so the files open with the copy of the program last run, whatever is chosen for model files in File, Settings. On Windows the extension gets a ProgID of its own, Sprite3D.Project, and is made to open with it; a choice made with Always in Windows' own How do you want to open dialog still wins. On Linux the project MIME type, application/x-sprite3d, goes into the application's desktop entry, with the model types if they are registered, and is made to open with it. On macOS the bundle's document types do this, and elsewhere there are no associations, so it does nothing.

Parameters
AMessage
Set to what went wrong; empty if nothing did.
Returns

True on success, or where there is nothing to do.
